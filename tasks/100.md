## **Tarefa 100 — Redesign da listagem de Projetos (quadro 03 do Design)**

Referência visual: `tasks/design/03-projetos-lista.dc.html` (protótipo do Claude Design; abrir no editor, não no navegador — o runtime `support.js` não está no repositório). Exportar o quadro como PNG em Design › Compartilhar › Exportar e salvar em `tasks/imagem/03-projetos-lista.png` para referência visual.

O protótipo é **referência de layout e hierarquia**, não código para copiar: ele usa HTML puro e estilos inline. A implementação deve usar os componentes shadcn/ui e os tokens do projeto (AGENTS.md, seção 3).

### 1. Escopo

Somente `src/modules/projects/project-list.tsx` e, se necessário, funções puras em `project-portfolio.ts` (com teste em `project-portfolio.test.ts`). Rota: `/projetos`.

Fora do escopo: visão Quadro (será a tarefa seguinte), API, banco, autenticação, permissões, Início, EAP.

### 2. Dados — já existem em `ProjectListRow`, não alterar a API

| Coluna do protótipo | Campo |
| --- | --- |
| Projeto (nome + código) | `name` + `glpiTicketId` (sem GLPI: `ID` + 8 primeiros caracteres de `id`, como hoje) |
| Fornecedor | `suppliers` (vários: separar por vírgula; `null`: “Indisponível”) |
| Gestor (avatar com iniciais + nome) | `ownerName` |
| Situação (selo) | `status` + `projectStatusKind` / `projectStatusLabel` / `EapStatusBadge` |
| Progresso (barra + %) | `progressBasisPoints` com `basisToPercent` / `formatBasis` |
| Início | `plannedStartAt` |
| Previsão | `plannedEndAt` |
| Atraso | `situation.delayDays` (> 0: “N dias” em vermelho; Em atenção sem atraso: “Risco”; demais: “No prazo”) |
| Ações (⋯) | menu atual (Abrir, EAP, Cronograma, Editar — respeitando `canEditProject`) |

Colunas atuais que **não podem sumir** sem decisão: Próxima entrega e Atualização. Proposta: mover Próxima entrega para o painel de detalhes/tooltip e manter Atualização como opção de ordenação.

### 3. Layout

1. Cabeçalho da página: sobretítulo “Portfólio institucional”, título “Projetos”, descrição; à direita “Exportar” (desabilitado com tooltip “Em breve” se não houver função) e “Novo projeto” só para quem já pode criar hoje.
2. Chips de situação (Todos, Crítico, Em atenção, Em execução, Em validação, Não iniciado, Concluído) com ponto colorido e contagem. Substituem os 6 cartões de indicador atuais e usam o mesmo filtro `filters.status` / `changeView`. Clicar no chip ativo volta para Todos.
3. Card da lista: barra de ferramentas (busca, Fornecedor, Gestor, “Limpar filtros”, alternador Lista | Quadro — Quadro desabilitado nesta tarefa), linha de contagem (“N projetos encontrados · ordenados por …”), tabela, paginação.
4. Linha de projeto crítico ou em atenção: realce de 3 px à esquerda na cor da situação (já existe).
5. Tabela com rolagem horizontal abaixo de 1040 px; nenhuma coluna some sem aviso.

### 4. Regras obrigatórias

- shadcn/ui: Button, Input, Badge/EapStatusBadge, Progress, DropdownMenu, Tabs, Tooltip, Avatar, OptionCombobox. Sem `<button>` nativo (corrigir paginação e “Limpar filtros”).
- Nenhum hex direto: usar tokens (`text-foreground`, `text-muted-foreground`, `border-border`, `bg-card`, `text-primary`). Cores de situação via `PROJECT_STATUS_COLOR` até os tokens `--status-*` existirem.
- Escala de texto do projeto (`text-body`, `text-secondary`, `text-label`, `text-page-title`); sem `text-[13px]`.
- Preservar: filtros, ordenação, paginação, abas Ativos/Concluídos/Arquivados/Todos, aviso de situações indisponíveis, estado vazio, spinner ao abrir, `motion-fade`, acessibilidade (link no nome, `aria-pressed`, `aria-live`).
- Sem dados fictícios.

### 5. Validação

`pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`; conferir em `/projetos` em 1440 px e 1024 px. Commit próprio só com autorização: `feat(projetos): listagem no novo padrão visual`.
