ETAPA 2 — Implementar a tela de login institucional do Sistema de Gestão de Projetos do IGEPPS.

## CONTEXTO
A fundação do gestao-projetos-web está concluída.
- Front-end: http://localhost:3001
- Backend Fastify: http://localhost:3000
- Better Auth já configurado.
- Cliente Orval já gerado.
- Regras existentes em .cursor/rules.

## REFERÊNCIA VISUAL
Utilize a imagem anexada como referência principal. Reproduza com alta fidelidade sua composição visual, mas adapte o conteúdo para o Sistema de Gestão de Projetos da CTIN/IGEPPS.

## REQUISITOS VISUAIS
1. Layout dividido em duas áreas no desktop:
   - Esquerda: fundo azul-marinho institucional, nome IGEPPS, CTIN, título do sistema e apresentação breve.
   - Direita: formulário de autenticação.
2. Utilizar tipografia moderna, espaçamento consistente e componentes shadcn/ui.
3. Utilizar os tokens semânticos do tema; não espalhar cores hardcoded.
4. Layout responsivo para desktop, tablet e celular.
5. Utilizar somente logotipos e brasões oficiais já disponíveis no projeto. Caso não existam, usar identificação textual provisória, sem inventar símbolos.
6. Não copiar os textos ou links específicos do sistema e-Ouve.
7. Não implementar links de recuperação de senha ou manual como se estivessem funcionais sem existir suporte real.

## REQUISITOS FUNCIONAIS
1. Criar rota /login.
2. Integrar o formulário ao cliente Better Auth existente, utilizando login por e-mail e senha.
3. Validar os campos e apresentar mensagens claras de erro.
4. Implementar indicador de carregamento e impedir envios duplicados.
5. Implementar opção de mostrar/ocultar senha.
6. Se o usuário já estiver autenticado, redirecionar para a área interna.
7. Proteger a rota interna inicial com verificação real da sessão no servidor.
8. Se o usuário não estiver autenticado, redirecionar para /login.
9. Preparar logout funcional para a próxima etapa.
10. Não utilizar apenas verificações visuais ou leitura da existência de cookies como autorização.

## SEGURANÇA
- Não habilitar cadastro público.
- Não implementar Google OAuth.
- Não armazenar senha ou token em localStorage.
- Não expor segredos.
- Preservar as permissões existentes no backend.
- Não modificar o backend ou o banco de dados.

## ESCOPO
Nesta etapa, implemente somente a tela de login e o fluxo de autenticação.

Após o login, apresente uma página interna mínima com identificação do usuário autenticado. O dashboard completo será desenvolvido na próxima etapa.

## VALIDAÇÃO
- Executar typecheck, lint e build.
- Testar redirecionamento de usuários autenticados e não autenticados.
- Testar login inválido.
- Testar login válido com uma conta de teste existente, se houver credenciais disponíveis de forma segura.
- Verificar responsividade e possíveis erros no navegador.

## ENTREGA
Apresente arquivos criados/alterados, testes executados, resultado da integração e eventuais pendências.

Ao concluir, pare e aguarde minha aprovação para a Etapa 3.
