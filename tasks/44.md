## **Autorização — Estabilização inicial do sistema IGEPPS**

Autorizo a execução controlada da primeira etapa de estabilização do Sistema de Gestão de Projetos do IGEPPS, conforme o diagnóstico apresentado.

### **1. Preservação do projeto**

Antes de qualquer alteração:

- Verifique o estado atual dos repositórios da API e do frontend.
- Confirme que nenhum arquivo sensível ou backup será incluído no Git.
- Crie um commit de segurança em cada repositório, preservando todas as alterações legítimas existentes.
- Não utilize `git reset --hard`, `git clean`, `git push --force` ou comandos destrutivos.
- Não envie commits para repositórios remotos.
- Se encontrar arquivos suspeitos ou segredos rastreados, interrompa a operação de commit e informe o problema.

### **2. Correção dos testes**

Corrija exclusivamente a preparação dos 15 testes que falham por ausência de datas planejadas.

Não remova a obrigatoriedade de datas do código de produção.

### **3. Separação dos testes**

Ajuste os scripts do backend para diferenciar:

- Testes unitários em memória, que não acessam o banco.
- Testes de integração, que dependem do banco de dados.

O comando padrão de testes deverá executar somente testes seguros em memória.

### **4. Proteção dos arquivos**

Reforce os arquivos `.gitignore` da API e do frontend para impedir o versionamento acidental de senhas, backups, dumps e arquivos de ambiente.

Não exclua nem mova os arquivos existentes.

### **5. Validação**

Execute apenas testes em memória, verificações de tipos e análises estáticas que não alterem dados persistentes.

Não execute testes de integração, migrações, seeds ou operações sobre o banco de dados.

### **6. Restrições obrigatórias**

- Não modificar funcionalidades existentes.
- Não alterar regras de negócio.
- Não modificar a estrutura do banco de dados.
- Não excluir tabelas, rotas ou arquivos.
- Não realizar refatorações fora do escopo.
- Preservar a interface, os componentes, as transições suaves e a identidade visual.
- Seguir as regras do CLAUDE.md.
- Economizar tokens, lendo somente os arquivos necessários.

### **7. Resultado esperado**

Ao concluir, apresente um relatório objetivo contendo:

1. Commits de segurança criados, com seus identificadores.
2. Arquivos modificados.
3. Resultado dos testes antes e depois.
4. Resultado das verificações de tipos.
5. Problemas que permaneceram pendentes.

Não avance para a próxima etapa automaticamente.
