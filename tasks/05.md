ETAPA 3A — LAYOUT PRINCIPAL DO SISTEMA DE GESTÃO DE PROJETOS IGEPPS/CTIN

O front-end gestao-projetos-web já possui Next.js, TypeScript, Tailwind, shadcn/ui, cliente Orval e autenticação Better Auth.

A tela de login foi aprovada e deve permanecer intacta.

## OBJETIVO
Implementar a estrutura visual da área interna do sistema, com alta fidelidade à imagem de dashboard anexada.

## ESCOPO
1. Criar layout autenticado com menu lateral, cabeçalho e área principal.
2. Utilizar identidade visual coerente com a tela de login aprovada.
3. Exibir nome e informações reais do usuário autenticado, quando disponíveis.
4. Criar menu lateral com:
   - Início;
   - Projetos;
   - Minhas Tarefas;
   - Entregas e Homologações;
   - Relatórios;
   - Administração.

5. Os itens sem funcionalidade implementada devem permanecer claramente indisponíveis ou não navegáveis.
6. Preparar navegação responsiva, com menu recolhível em telas menores.
7. Implementar logout funcional utilizando Better Auth.
8. Criar página inicial com estrutura visual semelhante à referência:
   - Título de boas-vindas;
   - Espaço para indicadores;
   - Espaço para gráficos;
   - Espaço para próximos marcos;
   - Espaço para listagem ou Kanban de projetos.

9. Nesta etapa, não preencher esses espaços com projetos, estatísticas ou datas fictícias. Utilizar estados vazios informativos até a integração com a API.
10. Aplicar os componentes e tokens semânticos já existentes no projeto.

## SEGURANÇA
- Preservar proteção de rotas e verificação de sessão.
- Não confiar apenas em permissões visuais.
- Respeitar os perfis definidos no backend.
- Não expor dados de projetos a usuários não autorizados.
- Não criar outra autenticação.

## RESTRIÇÕES
- Não modificar a tela de login.
- Não alterar backend, banco de dados ou migrations.
- Não inventar endpoints.
- Não instalar dependências desnecessárias.
- Não implementar todos os módulos de uma só vez.

## VALIDAÇÃO
- Executar typecheck, lint e build.
- Testar navegação e logout.
- Verificar desktop e mobile.
- Capturar screenshot do dashboard e comparar com a referência.

## ENTREGA
Apresentar arquivos alterados, resultados dos testes e captura de tela.

Ao concluir, aguardar minha aprovação antes de integrar os dados reais dos projetos.
