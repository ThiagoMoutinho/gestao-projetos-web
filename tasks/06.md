PREPARAÇÃO DO AMBIENTE DE DESENVOLVIMENTO — PRIMEIRO USUÁRIO DE TESTE

O Sistema de Gestão de Projetos IGEPPS já possui autenticação Better Auth e front-end Next.js, mas ainda não tenho uma conta para acessar o dashboard.

## OBJETIVO
Criar de maneira segura e controlada um usuário de teste no ambiente de desenvolvimento local, sem habilitar cadastro público.

## DADOS DO USUÁRIO
- Nome: Usuário de Teste PMO
- E-mail: pmo.teste@exemplo.com
- Perfil: PMO
- Senha: deverá ser informada de maneira segura durante a execução local, sem aparecer em arquivos versionados, logs ou relatórios.

## INSTRUÇÕES
1. Inspecione como o Better Auth está configurado e como os usuários são persistidos no PostgreSQL.
2. Verifique se já existe algum script administrativo de criação de usuários.
3. Se existir, reutilize-o.
4. Caso não exista, implemente um script de bootstrap exclusivo para desenvolvimento, utilizando os mecanismos oficiais de criação de usuários e hash de senha compatíveis com o Better Auth.
5. Garanta que o usuário receba o perfil PMO, respeitando o schema e as regras de autorização existentes.
6. Não inserir senha em texto puro no banco de dados.
7. Não utilizar SQL direto para criar credenciais ou gerar hash manualmente.
8. Não habilitar cadastro público.
9. Não modificar as permissões dos demais usuários.
10. Não executar migrations ou operações destrutivas.
11. Não criar dados fictícios de projetos.
12. O script deve funcionar somente em ambiente de desenvolvimento e impedir execução acidental em produção.
13. Se o usuário já existir, não sobrescrever sua senha ou perfil automaticamente.
14. Não registrar senhas, cookies, tokens ou segredos na saída do terminal.

## VALIDAÇÃO
- Confirmar que o usuário foi criado no banco de desenvolvimento.
- Verificar que o login por e-mail e senha funciona.
- Verificar que a sessão retorna o perfil PMO.
- Confirmar que o dashboard abre após autenticação.
- Testar o logout e o redirecionamento para /login.

## ENTREGA
Apresentar os arquivos criados ou alterados, o comando seguro para criar o usuário e os resultados dos testes.

Não avance para integração de projetos ou dashboard executivo.
